# ExoAstro: Exoplanet Detection & Vetting Platform

**ExoAstro** is an end-to-end, full-stack platform designed to automate the discovery, classification, and scientific validation of exoplanets using NASA's Kepler and TESS data. 

Built over a structured 15-day development cycle, this project transforms scattered Jupyter notebooks and complex research repositories into a streamlined **Python Machine Learning Pipeline** paired with a modern **Next.js + TypeScript Dashboard**.

---

## 🚀 Pipeline Architecture

The platform operates in five distinct stages:

1. **Data Acquisition (`src/data`)**: Integrates with MAST via `lightkurve` to fetch, clean, stitch, and flatten time-series light curve data.
2. **Feature Engineering (`src/features`)**: Uses Box Least Squares (BLS) to identify signals and generates AstroNet-standard **Global** (2001 bins) and **Local** (201 bins) phase-folded views. Includes cyclic data augmentation.
3. **Classification (`src/models`)**: Employs an **Advanced AstroNet 1D-CNN**, upgraded with ExoMiner-style Multi-Head Attention blocks, to score candidates.
4. **Diagnostic Vetting (`src/vetting`)**: Conducts physical sanity checks—such as Odd-Even depth discrepancy and Signal-to-Noise (SNR) calculations—to weed out Eclipsing Binaries (EBs) and false positives.
5. **Scientific Transit Fitting (`src/transit_fit`)**: Uses `PyTransit` (RoadRunner analytical model) to perform non-linear parameter fitting (extracting the planetary radius ratio $k$).

## ⚖️ Borrowed vs. Built

A core philosophy of this build was to stand on the shoulders of giants while maintaining strict architectural ownership. 

### What Was Borrowed (Lineage)
- **Lightkurve**: API interactions, BLS periodograms, stitching.
- **exoplanet-ml (AstroNet)**: Global/Local binning mathematics and baseline 1D CNN hyper-parameters.
- **ExoMiner**: Inspiration for injecting Attention mechanisms into the CNN.
- **LATTE**: The strategy for diagnostic plots and odd-even vetting tests.
- **PyTransit**: The core analytical transit modeling equations.

### What Was Built
- **The Integration Layer**: A unified, object-oriented Python codebase (`src/`) that orchestrates all the above tools into a single, cohesive, fault-tolerant pipeline.
- **Data Contracts**: Standardized JSON artifacts connecting the backend pipeline to frontend clients.
- **The Presentation Layer**: A bespoke Next.js (App Router), TailwindCSS, and TypeScript dashboard that translates raw Python outputs into an interactive, judge-friendly scientific product.
- **Automation CLI**: Dedicated scripts to fetch, preprocess, train, and generate PDF reports in batch.

## 💻 Quick Start

### 1. Python Pipeline Setup
```bash
# Install dependencies
pip install -r requirements.txt # (lightkurve, tensorflow, numpy, pytransit, reportlab)

# Run the end-to-end PoC on a known planet (e.g., Kepler-10b)
python scripts/run_poc.py

# Generate a PDF report
python scripts/generate_report.py --target "Kepler-10b"
```

### 2. Web Dashboard Setup
The web dashboard consumes the JSON/PNG/PDF artifacts generated by the Python pipeline (found in `web/public/data` and `web/public/plots`).

```bash
cd web
npm install
npm run dev
# Open http://localhost:3000 in your browser
```
